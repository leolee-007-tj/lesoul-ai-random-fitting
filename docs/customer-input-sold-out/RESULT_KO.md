# LESOUL 치수 입력과 품절 전용 목록

## 원인과 수정
선택 치수를 Number로 바로 변환해 공백·단위·잘못된 숫자가 서버 입력 검사에서 거부되어도, 추천 실패를 모두 ‘입력한 치수와 연결 상태’라는 문구로 표시했습니다.

비어 있는 선택 항목은 미입력으로 처리합니다. 165cm, 55kg, 전각 숫자, 소수점 쉼표를 해석하고 잘못된 입력은 ‘키: 80–240 cm 숫자로 입력하거나 비워 주세요’처럼 필드별로 안내합니다. 단위·수치를 추측하지 않고, 오류가 있으면 추천·이미지 요청 전에 중단합니다. 추천과 이미지 생성 모두 같은 정규화 값을 사용합니다. 입력 오류·추천 처리 실패·이미지 생성 실패를 구분하며 치수를 몰라도 비워서 추천을 요청할 수 있습니다. 실제 외부 모델·이미지 서비스를 호출한 검증은 아닙니다.

디스플레이와 /catalog 고객·게스트 상품 둘러보기에 판매 상품 / 품절 상품만 보기 전환을 추가했습니다. 기본 목록은 품절을 제외하며, 품절 탭은 예전 sold_out 상태까지 포함한 품절 상품만 표시합니다. 신상인 품절 상품도 그 탭에 모읍니다. 분류·브랜드·페이지 이동은 유지하고 비활성/VIP 공개 권한은 확대하지 않았습니다. 판매 목록의 AI 룩북에서도 품절 구성 상품이 섞인 이미지를 제외합니다. 품절 상품을 추천·구매 가능한 것으로 바꾸지 않았습니다.

## 검증과 복구
전체 414개/128파일 통과(9.79초), 타입 검사·클라이언트·서버 빌드 통과. 초기 검증은 4개 실패가 있었습니다. 기존 sparse checkout에서 빠진 원래 HTML 진입점과 SQL을 같은 HEAD에서 읽을 수 있도록 로컬 체크아웃 범위를 보완했습니다. 테스트 서명 설정은 일회성 공개 fixture만 사용했습니다. 번역 테스트의 오래된 인자 문자열 기대값을 현재의 기존 메타데이터 인자에 맞췄습니다. 운영 인증 설정 변경이나 실제 DB 적용은 없습니다. 원본 실패 로그를 보존합니다.

원인 재발 검사는 치수 파서 11개, 품절 분리 3개, 다국어 버튼 렌더링 2개, 잘못된 치수에서 요청 차단 1개를 포함합니다. 기존 카메라 닫기·중복 클릭·늦은 응답 무시 검사도 유지합니다.

실제 모델 호출 0, Root 요청 0, 운영 DB 쓰기 0. Manus 실사이트 동작·동기화 상태는 미검증입니다. GitHub main 반영 후 Manus의 최신 코드 적용 상태를 따로 확인해야 합니다. 복구 기준은 VALIDATION.json의 baseline_sha이며 실제 데이터는 변경하지 않았습니다.
